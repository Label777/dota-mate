# Dota Mate

Личный справочник союзников по Dota 2. Запоминайте, с кем играли, ставьте приватные оценки и заметки, а при новой встрече сайт напомнит историю.

## Версия на GitHub Pages (без сервера)

Достаточно файла `index.html`. Данные хранятся в вашем браузере.

- Матчи добавляются по ссылке (OpenDota или Dotabuff) или вручную.
- Соперники учитываются так же, как союзники: их можно оценивать, оставлять заметки, искать в списке игроков и видеть напоминание о прошлых встречах.
- Кнопка «Синхронизировать матчи» обращается к OpenDota прямо из браузера. Нужна настройка Dota 2 «Открытые данные матчей».
- Аватары игроков подгружаются из OpenDota по публичному ID, адрес картинки сохраняется в данных. Отключить можно в настройках. Если картинки нет, показаны инициалы.
- Входа через Steam на Pages нет: ему нужен сервер. Вместо входа в настройках указывается Steam ID.
- Резервная копия в настройках переносит данные на другое устройство.

### Как включить Pages

1. Откройте репозиторий на GitHub: **Settings → Pages**.
2. В разделе **Build and deployment** выберите **Deploy from a branch**, ветку `main`, папку `/ (root)`.
3. Через минуту сайт появится по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

## Профиль игрока

Свой профиль открывается по аватару и нику в шапке сайта. Вкладка «Найти профиль» (пятый пункт меню) ищет и показывает статистику любого игрока по открытым данным OpenDota. Работает и на GitHub Pages, сервер не нужен.

- **Поиск.** Принимает SteamID64, числовой Steam ID, `STEAM_0:X:Y`, `[U:1:N]` и ссылки `steamcommunity.com/profiles/…`, `opendota.com/players/…`, `dotabuff.com/players/…`. Ссылки вида `/id/имя` без ключа Steam API разобрать нельзя, сайт честно об этом говорит. Последние открытые профили запоминаются в браузере.
- **История матчей.** Герой с иконкой, результат, дата, длительность, K/D/A, GPM/XPM, добитые крипы, позиция. Фильтры по герою, результату, позиции и периоду, подгрузка по 100 матчей. Изменение MMR по матчам OpenDota не отдаёт, поэтому столбца нет.
- **Оценка игры.** Столбец «Оценка» и карточка «Оценка игр»: 0 — сыграл как обычно, плюс лучше, минус хуже (от −50 до +50, целые числа). Считается по (K+A)/D, GPM и XPM относительно твоих же средних (на герое, если на нём от 5 матчей, иначе по всем загруженным); результат матча не учитывается. Нужно не меньше 8 матчей с данными, иначе оценки нет («—»). Формула в `matchScores` (`js/analytics.js`).
- **Статистика** за 7 дней, 30 дней и всю загруженную историю: матчи, винрейт, средние K/D/A, GPM, XPM, длительность, серии. Нет данных — показывается «—», а не 0. Если история загружена не целиком, сайт пишет об этом.
- **Герои.** Лучшие, для развития и худшие: порог матчей по умолчанию 5, меняется кнопками. Порядок учитывает размер выборки (интервал Уилсона), под каждым героем есть пояснение.
- **Позиции 1–5.** OpenDota не хранит позицию, а линии есть только у разобранных (спарсенных) матчей. Сайт сам проверяет 20 свежих матчей после загрузки, кнопка «Определить позиции» проверяет ещё до 30. Если матч разобран: три героя команды с наибольшим золотом — кор-роли, линии раскладывают их на 1, 2, 3, остальные двое получают 4 и 5. Если нет: позиция остаётся «Не определена», приблизительные значения (вроде «≈ Кор» по золоту) сайт не показывает: в столбце «Позиция» только точные данные. Кнопка «Отправить на разбор в OpenDota» ставит до 10 неразобранных матчей в очередь разбора (`POST /request/{id}`); через несколько минут нажмите «Перепроверить неточные». Результаты сохраняются в браузере.
- **Графики** (SVG без библиотек): винрейт нарастающим итогом, победы и поражения по дням или неделям, динамика (K+A)/D, серии, MMR. MMR рисуется только если игрок сам открыл рейтинг в профиле, иначе сайт его не придумывает.
- **Анализ и «На чём играть дальше»** строятся по понятным правилам (код в `js/analytics.js`), при нехватке данных сайт пишет, чего именно не хватает. Это корреляции по прошлым играм, а не причины.

Закрытый профиль (в Dota 2 выключено «Открытые данные матчей») показывает пустое состояние: получить скрытые данные нельзя.

### Как устроено

| Файл | Роль |
|---|---|
| `js/dotaapi.js` | Слой данных: единственное место, знающее про OpenDota. Кэш (память и localStorage), очередь запросов, обработка 404/429/5xx/таймаутов. Чтобы сменить источник, достаточно реализовать тот же интерфейс. |
| `js/analytics.js` | Чистые расчёты без DOM и сети: фильтры, винрейт, серии, герои, позиции, ряды для графиков, рекомендации. |
| `js/profile-ui.js`, `css/profile.css` | Интерфейс раздела. |
| `tests/` | Тесты (`npm test`, Node 18+, без зависимостей). |

Ключей в браузерном коде нет. OpenDota без ключа даёт примерно 60 запросов в минуту и 2000 в день с одного адреса; на Pages запросы идут из браузера пользователя, на сервере через прокси с кэшем.

## Репутация и поведение игроков

Вкладка «Репутация» проверяет игрока или матч и собирает отметки в одном месте. Принцип: факты игры, статистические отклонения, жалобы и решения людей хранятся и показываются **отдельно**, а оценка раскрывает, из чего сложилась.

Адреса: `#/profile/<id>`, `#/match/<id>`, `#/episodes/<id>`, `#/timeline/<id>`, `#/network/<id>`, `#/report/<id>` (публичный отчёт), `#/reports`, `#/party`, `#/watchlist`, `#/appeals`, `#/mod`. У каждого игрока, матча и отчёта своя ссылка.

| Страница | Что делает | Где работает |
|---|---|---|
| Поиск | Игрок по Steam ID / SteamID64 / ссылке и матч по Match ID, недавние, объяснение расчёта | везде |
| Профиль | Карточка репутации с блоком «Почему сформирована эта оценка?», бейджи аномалий в таблице матчей, фильтр «Аномалии и факты игры» / «Решения модераторов», ссылка на отчёт по каждому матчу | везде |
| Матч | Участники, статистика, сигналы по игрокам (выход из матча, смерти заметно выше, чем у остальных в этом матче), кнопка «Сверить с историей игрока», подтверждённые отметки по матчу | везде (отметки модераторов только с сервером) |
| Эпизоды / Хронология | Факты игры, A · статистические аномалии, B · жалобы без решения (только счётчик), C · решения модераторов; фильтры по категории и периоду | везде; B и C только с сервером |
| Party Safety | До 5 Steam ID, сводка по каждому, без вердикта «опасная группа» | везде |
| Сеть | Партнёры по матчам (OpenDota `peers`), фильтры по периоду и числу общих матчей, ссылки на общие матчи | везде |
| Публичный отчёт | Дата формирования, источники, методика, ограничения; строится заново при каждом открытии | везде |
| Жалобы, Обжалования, Модерация | Форма жалобы, «Мои жалобы», обжалование отметки, панель модератора, журнал действий | **только с сервером** и входом через Steam |
| Наблюдение | Список игроков и уведомления трёх типов (сообщения, аномалии, решения) | на сервере хранится в аккаунте, без сервера локально в браузере |

### Как считается репутация

Правила лежат в `js/reputation.js` и покрыты тестами. Один и тот же код работает в браузере и на сервере.

- **Баллы дают только:** эпизоды, подтверждённые модератором (по 25, максимум 70); матчи с необычным числом смертей относительно *собственной* нормы игрока и его героя (по 2, максимум 10); повторяемость таких матчей (максимум 16); высокая доля матчей, покинутых по данным игры (6 или 12); неподтверждённые жалобы независимых авторов (по 2, максимум 8, считается меньшее из «разных авторов» и «разных матчей»).
- **Баллов не дают:** поражения, винрейт, низкий K/D/A, число жалоб от одного автора, скрытые данные.
- Без подтверждения модератором итог не превышает 46 из 100, поэтому уровень «Высокий» недостижим.
- Меньше 20 матчей: оценки нет (не ноль, а «недостаточно данных»); меньше 15 подходящих матчей: аномалии не ищутся.
- Индекс 0–100 экспериментальный, метод открыт в карточке.

### Чего система не умеет (и не делает вид)

- OpenDota не отдаёт данные о намеренном кормлении, сломанных предметах, блокировке союзников и т. п. Такие эпизоды система **не определяет сама**: для них только жалобы с проверкой модератором.
- Статистическое отклонение не доказывает умысел: причиной могут быть сложная игра, смена роли, сильный соперник.
- Закрытые профили и матчи недоступны. Позиция показывается только когда она надёжно определена.
- Граф «Сеть» показывает связи только выбранного игрока; связи между другими игроками не запрашиваются. Выводов о сговоре или о принадлежности аккаунтов одному человеку не делается.
- В таблице матчей фильтр «Решения модераторов» показывает только публичные подтверждённые отметки. Непроверенные жалобы по матчам не публикуются.

### Жалобы, модерация, защита от злоупотреблений (сервер)

Все правила проверяются на сервере (`server/community.js`), интерфейс их только показывает.

- Вход через Steam обязателен. Лимиты: 5 жалоб в сутки, 20 нерассмотренных одновременно, не больше 3 жалоб на одного игрока в неделю; одна жалоба на пару «автор + обвиняемый + матч» (повтор отклоняется).
- Жалоба принимается только если и автор, и обвиняемый есть среди участников матча по данным OpenDota (матч не старше 60 дней). Ссылки на доказательства: только `https`, до 3, без IP-адресов, логинов и ссылок на программы, архивы и HTML. Файлы не загружаются.
- Публично жалоба не видна. Обобщённый счётчик непроверенных жалоб показывается, только если их подали минимум два разных автора по двум разным матчам. Авторы и тексты жалоб не публикуются.
- Если на одного игрока за сутки жалуется много разных авторов, жалобы помечаются «всплеск» для модератора. Обвиняемый или участник матча может сообщить о ложной жалобе.
- Статусы: Новый, Ожидает проверки, Требует дополнительных данных, Подтверждён модератором, Не подтверждён, Отклонён, Оспаривается, Закрыт. Допустимые переходы закреплены на сервере; каждое решение требует обоснования и пишется в журнал (`moderation_actions`). Модератор не может рассматривать дело, где он автор или обвиняемый.
- Подтверждённую отметку можно оспорить: она получает статус «Оспаривается» и **не входит в оценку** до решения. Если модератор снимает отметку, публичный профиль и отчёт обновляются сразу.
- Модераторы задаются переменной `MODERATORS`. Без неё модерация недоступна никому.

## Версия с сервером (вход через Steam, данные на сервере)

Файл `server.js` запускает тот же сайт с входом через Steam OpenID, хранением данных на сервере и загрузкой матчей через сервер. Прокси OpenDota (`/api/od/…`) отдаёт только публичные данные, проверяет параметры, кэширует ответы и ограничивает число запросов; раздел «Профиль» работает через него и без входа. Для сайта и прокси нужен Node.js 18 или новее; для жалоб, модерации и серверного списка наблюдения нужен **Node.js 22.5 или новее** (встроенная SQLite `node:sqlite`, она помечена как экспериментальная и при запуске печатает предупреждение). На более старом Node сервер работает, а функции сообщества честно отключены. Внешних зависимостей нет.

```bash
PUBLIC_URL=https://dotamate.example.com PORT=3000 node server.js
```

| Переменная | Назначение |
|---|---|
| `PUBLIC_URL` | Адрес сайта без `/` в конце. Должен совпадать с адресом, на который Steam вернёт пользователя. |
| `PORT` | Порт, по умолчанию 3000. |
| `DATA_DIR` | Папка данных, по умолчанию `./data`. |
| `SESSION_SECRET` | Ключ подписи сессий. Если не задан, создаётся в `DATA_DIR/secret.key`. |
| `OPENDOTA_API_KEY` | Необязательно. Ключ OpenDota повышает лимиты запросов. Хранится только на сервере и в браузер не попадает. |
| `STEAM_API_KEY` | Необязательно. Нужен только для разбора ссылок вида `steamcommunity.com/id/имя` (официальный Steam Web API, `ResolveVanityURL`). |
| `MODERATORS` | Steam ID или SteamID64 модераторов через запятую. Без значения модерация недоступна. |
| `DB_FILE` | Файл SQLite сообщества, по умолчанию `DATA_DIR/dotamate.sqlite`. Миграции применяются при запуске. |
| `ANTHROPIC_API_KEY` | Необязательно. Включает ИИ-чат помощника. Хранится только на сервере. Без ключа помощник работает как справочник без ИИ. |
| `ASSISTANT_MODEL` | Модель помощника, по умолчанию `claude-sonnet-5-5`. |
| `ANTHROPIC_BASE` | Только для тестов: другой адрес API Anthropic. |
| `OPENDOTA_BASE` | Только для тестов: другой адрес источника данных. |
| `DEV_LOGIN` | `1` включает проверочный вход без Steam. На публичном сервере не включайте. |

Перед сервером нужен HTTPS (nginx, Caddy). GitHub Pages сервер запускать не умеет, для него подойдёт любой хостинг с Node.js.

## Личные заметки, теги и рекомендации

Всё ниже видно только вам и не влияет на публичную репутацию игрока. Работает и на GitHub Pages (данные в браузере), и на сервере (данные в вашем аккаунте).

- **Теги игроков.** Готовые («Хороший тиммейт», «Хороший саппорт», «Можно в пати», «Кор», «Смурф», «Токсик», «Избегать») и свои. Ставятся в карточке игрока, видны в списках.
- **Счёт с игроком.** В карточке и в списке: ваши победы и поражения в матчах вместе и против него, например «вместе: 9 (7–2)».
- **Вкладки на странице «Игроки».** «Для пати» (до пяти союзников по вашему винрейту и средней оценке, формула раскрыта на странице), «Без оценки», «Избегать», «Статистика» (с кем играете чаще всего, кого оцениваете выше и ниже, винрейт в матчах с высоко и низко оценёнными союзниками).
- **Оценить всех.** Один экран на весь состав матча: звёзды, короткая заметка и быстрые теги. Открывается из карточки матча и с главной.
- **Фильтры и поиск.** По тегу, по диапазону средней оценки, с оценкой или без. Поиск ищет ник, Steam ID, текст заметок к матчам и об игроках, заметки о героях и теги.
- **Заметки по героям.** «На Pudge часто фидит»: показываются в составе матча, когда игрок вышел на этом герое.
- **Напоминания.** На главной: «давно не играли с…» для игроков с оценкой от 4 или хорошим тегом, если прошло 14 дней и больше. Можно отложить или выключить в настройках.
- **Экспорт и импорт (.json).** Настройки, «Экспорт и импорт». Импорт проверяет файл и очищает его содержимое, показывает, что внутри, и предлагает «Добавить к моим данным» (ваши данные не удаляются, более новая оценка из файла побеждает) или «Заменить».

Не сделано: несколько Steam ID в одном аккаунте. Определение необычного поведения (много смертей, выходы из матчей) уже есть в разделе «Репутация».

## Главная, быстрый поиск и подсказки

- **Главная («Обзор»).** Поиск игрока, показатели, динамика матчей, риск по знакомым игрокам, таблица игроков, активность и быстрый доступ; подробности в разделе «Оформление и дизайн-система». Если данных нет, главная прямо говорит, с чего начать.
- **Адреса разделов.** `#/matches`, `#/players`, `#/settings`, `#/find` открывают нужный раздел напрямую, обновление страницы его сохраняет.
- **Меню.** На компьютере вкладки идут в одну строку; на экранах уже 1200 px остаются только иконки (название видно в подсказке). На телефоне внизу четыре главных раздела и «Ещё» с остальными.
- **Быстрый поиск (Ctrl+K или кнопка лупы в шапке).** Один список: разделы, действия (синхронизация, оценить всех), игроки, матчи и профили. Стрелки и Enter, Esc закрывает.
- **Подсказки при наведении.** Работают на кнопках, вкладках, заголовках таблиц, полях и значках. Тексты лежат в одном словаре `js/tips.js`, поэтому новые элементы получают подсказку без отдельной вёрстки. Подсказки показываются и при фокусе с клавиатуры; на сенсорных экранах при наведении их нет.

## Профили всех игроков и авто-оценка

У каждого игрока в матче есть карточка, в том числе у тех, кто скрыл профиль или у кого нет Steam ID: открывается из строки матча. В ней: герой, K/D/A, GPM/XPM, урон, лечение, авто-оценка и разбор по частям.

**Авто-оценка по игре** (1–5 звёзд, 0–100 очков) считается по цифрам матча и никак не связана с вашими личными оценками:

- вклад (60%): GPM, XPM, убийства в минуту, добитые крипы, урон по героям, лечение и урон по строениям относительно процентилей героя из OpenDota `/benchmarks`;
- участие (20%): (убийства + помощь) относительно убийств команды;
- выживание (20%): смерти в минуту.

Если по герою нет бенчмарков, игрок сравнивается с остальными участниками того же матча. Матчи короче 10 минут не оцениваются; выход из матча ограничивает оценку 15 очками. Итог по игроку усредняется по всем его матчам у вас и показывает тренд.

Ограничения: это эвристика по числам. Она не видит общение, поведение и роль в команде (саппорт с малым GPM будет оценён по лечению и участию, но не идеально). Подробности матча берутся из открытых данных OpenDota, поэтому у необработанных матчей оценки может не быть. Результаты хранятся только в вашем браузере (`dotamate.perf.v1`) и на сервер не отправляются. Фоновая догрузка включается и выключается в настройках, там же можно очистить кэш.

## Теги и репутация возле ника

Рядом с ником (список игроков, состав матча, карточки) показываются ваши теги и короткий значок репутации: «Нет сигналов», «Мало данных», «Проверить», «Подтверждено», «Давно не играл». Значок считается теми же правилами, что и раздел «Репутация» (факты игры, статистические отклонения, решения модераторов на сервере), в фоне и только для игроков на экране: 1–2 запроса к OpenDota на игрока. Результат хранится в браузере 12 часов (`dotamate.repq.v1`), в настройках его можно выключить и очистить. У игроков со скрытым профилем стоит «Профиль скрыт»: без Steam ID другие матчи не найти.

Значок не вывод о поведении: «Нет сигналов» не гарантия, «Проверить» не приговор, подробности и основания в разделе «Репутация».

## Драфт в реальном времени

Вкладка «Драфт» показывает выбор и баны героев обеих команд, чей сейчас ход и сколько осталось времени, и подсказывает, кого выбрать против уже выбранных врагов.

**Как данные попадают на сайт.** Dota 2 умеет сама отправлять состояние игры (Game State Integration, GSI), но только на адрес вашего компьютера. Страница на GitHub Pages принять их не может, поэтому нужен маленький мост `bridge/dota-mate-bridge.js` (один файл, Node.js 18+, без зависимостей). Он слушает только `127.0.0.1`, принимает данные от игры и передаёт странице блок драфта, статус матча, вашу сторону и свой Steam ID с ником (для оверлея игроков; у наблюдателя ещё Steam ID и id героев всех игроков). В интернет он ничего не отправляет, остальное содержимое GSI (здоровье, предметы, карта) отбрасывается.

1. Скачайте мост на странице «Драфт» (кнопка «Подключить Dota 2») и запустите: `node dota-mate-bridge.js`. Он напечатает ссылку, текст cfg-файла и сохранит токен в `~/.dota-mate-bridge.json`.
2. Положите cfg в `steamapps/common/dota 2 beta/game/dota/cfg/gamestate_integration/` или выполните `node dota-mate-bridge.js --install "<папка игры>"`.
3. В Steam, свойства Dota 2, параметры запуска: `-gamestateintegration`. Перезапустите игру.
4. Откройте ссылку из консоли моста. Адрес и токен запоминаются в браузере, из адресной строки токен убирается. Страница сама переподключается, если мост перезапустили.

Без игры: `node dota-mate-bridge.js --demo` или кнопка «Демо» на странице проигрывают записанный драфт. Он честно подписан как демонстрация. Если Dota 2 недоступна, драфт можно вести вручную: нажимайте героев, баны и выборы вносятся для любой стороны, есть отмена.

**Отдельное окно.** Кнопка «Отдельное окно» открывает компактную версию (`#/draft?w=1`): только доска, подсказки и лента, без шапки сайта. Окно подключается к тому же мосту, поэтому его можно поставить рядом с игрой, в том числе на второй монитор. Это обычное окно браузера: оно не встраивается в Dota 2 и не лезет в её процесс. Поверх игры оно видно, если Dota 2 запущена в режиме «в окне» или «окно без рамки»; поверх полноэкранного режима браузер окно не покажет. Постоянное положение «поверх всех окон» браузер не гарантирует.

**Безопасность для аккаунта.** Мы не меняем файлы игры и не внедряемся в неё: в папку `cfg/gamestate_integration` кладётся один текстовый файл настроек, и это штатный механизм Valve для внешних программ. Гарантий от Valve у нас нет, но известных случаев блокировок за него нет.

**Подсказки.** Для каждого кандидата берётся его винрейт против каждого выбранного врага (публичные матчи OpenDota, `/heroes/{id}/matchups`), сглаживается `(победы + 25) / (игры + 50)`, чтобы малые выборки не давали крайних значений, и усредняется. Рядом видны числа по каждому врагу, число данных и ваши собственные игры на этом герое (если указан Steam ID). Фильтры по атрибуту и роли, сортировка «против врагов» или «мои герои». Чего подсказки не учитывают: союзников, позицию, патч и рейтинг. Это ориентир.

**История.** Драфт из игры сохраняется в браузере сам, когда он закончился (до 50 записей, хранятся только ID героев, сторона и номер матча). Ручной и демо сохраняются кнопкой.

**Чего не гарантируется.** Формат блока `draft` взят из описаний открытых библиотек GSI, с настоящим клиентом Dota 2 он здесь не проверялся: автоматические тесты используют поддельные пакеты. Присылает ли клиент блок драфта в вашем режиме игры (например, в обычной очереди), зависит от Valve; если не присылает, мост напишет об этом в консоли. Игра не раскрывает Steam ID других игроков лобби, поэтому ваши заметки о них на этой странице не показываются. Браузер Safari может запретить HTTPS-странице подключаться к `http://127.0.0.1`; Chrome, Edge и Firefox разрешают. Приём GSI на сервере в интернете сознательно не сделан: игра отправляет данные только на локальный адрес.

После правок `js/draft.js`, `server/gsi-hub.js` или `tools/gsi-bridge.js` пересоберите мост: `node tools/build-bridge.js` (тест проверяет, что файл актуален).

## Оверлей игроков (Live Draft Intelligence)

Компактная панель с десятью игроками матча: Radiant и Dire, до пяти карточек в каждой. На карточке: ник, Steam ID и его источник, винрейт и число игр, средние K/D/A, три любимых героя (игры и винрейт), форма последних матчей (победы выше, поражения ниже, различимо без цвета), число сигналов для проверки и время обновления данных. По нажатию на карточку открывается подробная панель: последние матчи с датой и результатом, сравнение на герое с обычными показателями, сигналы с объяснениями, источник и возраст данных, ссылка на полный профиль.

**Как устроено.** `Dota 2 (GSI) → мост (127.0.0.1) → overlay.html → состояние матча → служба статистики → OpenDota`. Мост тот же, что для вкладки «Драфт»: в нём лишь расширен набор передаваемых полей.

| Модуль | Роль |
|---|---|
| `js/draft.js` (`pickGSI`) | пропускает из GSI только проверенные поля: свой Steam ID и ник, сторону, `team_slot`, у наблюдателя те же поля по всем игрокам, id героев |
| `js/live-match.js` | адаптер пакета, жизненный цикл матча (`idle → draft_detected → resolving_players → loading_stats → ready → in_game → finished`, плюс `disconnected`), изоляция матчей (epoch), определение личности игроков |
| `js/live-stats.js` | кэш по accountId, очередь, дедупликация, backoff, сводка статистики, сигналы |
| `js/overlay.js`, `css/overlay.css`, `overlay.html` | интерфейс и связка |
| `overlay-app/` | необязательная обёртка Electron: прозрачное окно поверх игры и глобальная горячая клавиша |

**Запуск.**
1. Мост запускается как для драфта (раздел выше): `node dota-mate-bridge.js`. Если вы ставили cfg раньше, перезапишите его (`--install`): в новый cfg добавлен раздел `hero` (нужен режиму наблюдателя).
2. Откройте `overlay.html` рядом с сайтом (`https://label777.github.io/dota-mate/overlay.html`) или кнопку «Оверлей игроков» на вкладке «Драфт». Адрес и токен моста общие с вкладкой «Драфт»; если их там не задавали, введите в настройках оверлея (⚙).
3. Окно можно поставить поверх игры, если Dota 2 запущена «в окне» или «окно без рамки». Для постоянного «поверх всех окон» и глобальной горячей клавиши есть обёртка: `cd overlay-app && npm install && npm start` (нужен Electron, он ставится отдельно и сайт не затрагивает).

**Кто считается идентифицированным.** Состояния: `identified` (Steam ID получен из игры), `pending` (ждём), `unavailable` (источник его не даёт), `private` (профиль скрыт или статистику источник не отдаёт), `error` (ошибка загрузки). Steam ID берётся только из документированных полей GSI: `player.steamid` (свой аккаунт) и `player.team2/team3.playerN.steamid` (режим наблюдателя). Обычный клиент игрока чужие Steam ID не отдаёт, поэтому на практике карточка заполнена у вас, а остальные девять показывают «Игрок не идентифицирован» с причиной. Мы никогда не сопоставляем игрока по нику, номеру слота, составу героев, аватару или прошлым матчам и не подставляем чужой ID. Два игрока с одинаковым ником остаются разными карточками. Если вы сами знаете ID (друзья из пати, ссылка из матча), его можно указать вручную кнопкой «Указать» (принимаются Account ID, Steam ID и ссылки opendota/steamcommunity, ники нет); такая карточка подписана «указан вручную», запись живёт только в этом матче.

**Статистика.** Для каждого ID оверлей один раз за срок кэша запрашивает `/players/{id}`, `/wl`, `/heroes` и последние 100 матчей, всего четыре запроса, остальное считается на месте. Метрика, которую нельзя посчитать (нет `wl`, меньше пяти матчей с K/D/A, нет героев), не показывается: нулей вместо отсутствующих данных нет. Приватный профиль и игрок без публичных матчей по ответу OpenDota неразличимы, карточка пишет об этом прямо.

**Кэш и очередь.** Все числа в одном месте, `CONFIG` в `js/live-stats.js`: свежесть 30 минут, показ устаревшего кэша до 24 часов (экран заполняется сразу, обновление идёт в фоне), два игрока одновременно, ручное обновление не чаще раза в минуту, не больше трёх попыток подряд. Одинаковые запросы объединяются. HTTP 429 ставит всю очередь на паузу (по `Retry-After`, не меньше 30 секунд), сетевые сбои повторяются с растущей задержкой, бесконечных циклов нет. Начался новый матч: ожидающие задания отменяются, готовый ответ старого матча в новый не доставляется. Матч закончился: запросы и повторы прекращаются. Уже идущий запрос прервать нельзя (слой данных не умеет), он дойдёт до конца, но его результат не попадёт в новый матч.

**Сигналы.** Используется существующая система раздела «Репутация» (`DMRep.detectAnomalies` и `computeReputation`), второй системы нет. Игровая статистика (винрейт, K/D/A, герои, форма) и сигналы показываются раздельно. Сигнал это отклонение от собственной нормы игрока (например, необычно много смертей в матче по сравнению с его же матчами на этом герое) или факт, записанный игрой (`leaver_status`). У каждого сигнала есть дата, герой, наблюдаемые значения, объяснение, размер выборки и ссылка на матч, а рядом сказано, что возможны другие объяснения. Нужно хотя бы 15 матчей с длительностью и смертями, иначе пишется «мало данных». Низкий KDA, поражения, необычный герой и малый опыт на герое сигналов не создают. Общего числа вроде «процента руина» нет, итог по методике репутации без решения модератора не бывает выше «требует проверки». Решения модераторов и жалобы в оверлее не используются (нужен сервер).

**Настройки** (хранятся в браузере): режим «компактный/подробный», свернуть, масштаб 70–150 %, прозрачность 40–100 %, анимации, какие метрики показывать, горячая клавиша скрытия (по умолчанию `Alt+Shift+D`), положение панели (перетаскивается за шапку) и ширина. Анимации выключаются и системной настройкой «уменьшить движение».

**Безопасность.** Мост слушает только `127.0.0.1`, проверяет Host (защита от DNS rebinding), токен, размер и структуру пакетов, не отправляет ничего в интернет и пишет на диск только файл с токеном `~/.dota-mate-bridge.json`. Из GSI проходят только перечисленные выше поля, золото, предметы и позиции отбрасываются. Оверлей принимает от моста только JSON определённой формы, адрес моста обязан быть `127.0.0.1` или `localhost`, ссылок и команд из сообщений он не исполняет. CSP страницы разрешает только свои скрипты, мост на localhost, OpenDota и картинки героев Steam. Телеметрии нет, ключей API нет. Новых зависимостей у сайта нет; у обёртки одна, `electron`, без дополнительных разрешений.

**Тесты.** `node --test tests/live-match.test.js tests/live-stats.test.js` (38 проверок: драфт, десять ID, часть ID, задержка, отсутствие ID, одинаковые ники, пустой и приватный профиль, 429, недоступный API, один запрос на игрока, изоляция матчей, остановка по концу матча, потеря моста, нули вместо отсутствующих данных, низкий KDA, малая выборка) и `python3 tests/e2e/overlay_e2e.py` (настоящий мост и поддельный OpenDota: все состояния интерфейса, настройки, горячая клавиша, перетаскивание, ручной ввод, переподключение).

**Ограничения.**
- Формат GSI взят из описаний открытых библиотек. С настоящим клиентом Dota 2 мы это не проверяли: тесты шлют на мост пакеты, собранные по этому формату.
- Чужие Steam ID во время драфта игрой не раскрываются (клиент игрока отдаёт только свой). Полные десять карточек возможны в режиме наблюдателя или если ID известны вам и введены вручную. Мы не обходим это ничем, кроме документированных полей.
- Игра в блоке `draft` не связывает выбранного героя с игроком. Герой на карточке показан только там, где GSI даёт соответствие (наблюдатель; у себя в игре).
- Роль (кор или саппорт) оверлей не определяет: по публичной статистике это ненадёжно. Кнопка «Определить линию» показывает самую частую линию по `lane_role` OpenDota (нужно 10 матчей с данными) и честно называет это линией, а не ролью.
- Оверлей поверх эксклюзивного полноэкранного режима невозможен без внедрения в игру, чего мы не делаем. Нужен режим «в окне» или «окно без рамки». Обёртка Electron написана, но в этой среде не запускалась (нет доступа к npm), проверена только загрузка `overlay.html` как файла в Chromium.
- Новый матч появляется в OpenDota не сразу, свежие игры в истории могут отсутствовать. Данные OpenDota публичны и неполны.
- Safari может запретить HTTPS-странице подключаться к `http://127.0.0.1`; в таком случае откройте оверлей из обёртки или локально.

## Помощник и оформление

Кнопка помощника в правом нижнем углу открывает панель с подсказками по сайту. Работает в двух режимах:

- **Справочник (без ИИ).** Готовые ответы про синхронизацию, профиль, репутацию, жалобы, обжалования и лимиты. Работает везде, в том числе на GitHub Pages, ничего никуда не отправляет.
- **ИИ-чат.** Включается, только если на сервере задан `ANTHROPIC_API_KEY` и пользователь вошёл через Steam. Ключ остаётся на сервере. Системная инструкция лежит в `server/assistant-prompt.txt`: помощник объясняет только то, что сайт умеет на самом деле. Лимиты: 20 вопросов в 10 минут на аккаунт, 12 последних сообщений и до 2000 символов в каждом.

Приватность: в ИИ-чате текст ваших сообщений и название текущего раздела уходят через сервер в Anthropic. Оценки и заметки об игроках не отправляются, если вы сами не вставите их в вопрос.

## MVP и худший игрок матча

Для каждого матча со статистикой сайт определяет двух игроков: с наибольшим положительным вкладом (**MVP**) и с самым слабым совокупным статистическим результатом (**худший**). «Худший» — это худший результат по цифрам этого матча, а не доказательство саботажа или руина: оценка не видит общение, тильт, решения и роль в драфте.

**Где видно.** Отметки «MVP: …» и «Худший: …» в списке матчей и в окне матча (оценка, причины, полнота данных, версия алгоритма, таблица на десять игроков); фильтры «Матчи, где я MVP» и «Матчи, где я сыграл хуже всех»; сводка со своей долей над списком; блок в профиле знакомого игрока (сколько раз он был MVP и худшим, доля при истории от 5 матчей); блок, фильтр и отметки в разделе «Найти профиль» (любой игрок OpenDota, кнопка «Определить MVP и худшего»); управление в «Настройках».

**Алгоритм (`js/impact.js`, версия `impact-1`).** Вход: запись матча из кэша статистики (`DMPerf.fromDetail`: убийства, смерти, помощь, золото и опыт в минуту, урон по героям, лечение, урон по строениям, выход из матча, победитель; у разобранных матчей ещё оглушения и варды) и нормы героев OpenDota (`/benchmarks`).
- Из сравнения исключаются игроки, вышедшие из матча, и игроки с неполными данными (меньше двух третей показателей). Если честно сравнивать можно меньше восьми игроков, матч короче 10 минут или данных нет, статусы не назначаются: «Недостаточно данных для определения MVP».
- Пять независимых показателей от 0 до 1: участие в убийствах команды, смерти (относительно среднего по матчу и по команде), KDA (место среди игроков), урон по героям и золото с опытом. Урон и экономика сравниваются с типичными цифрами **того же героя**, поэтому саппорт не проигрывает керри только из-за меньшего фарма и убийств. Если нормы героя нет, урон сравнивается с золотом внутри матча, а экономика не используется.
- Оценка MVP = взвешенное среднее (участие 26%, урон 25%, экономика 25%, смерти 14%, KDA 10%, веса пересчитываются по имеющимся показателям) плюс бонусы: поддержка до +12 (лечение, оглушения, варды, только вверх), урон по строениям до +6, победа команды +4. Индекс слабости считается так же, но с упором на смерти (30%) и за вычетом бонусов поддержки и строений.
- Статус получает лидер, если оценка не ниже порога (MVP от 60, худший от 55) и отрыв от второго места не меньше 1 балла. Иначе показывается «Нет однозначного лидера» или «Нет выраженного MVP». Случайный выбор не используется; MVP и худший всегда разные игроки.
- Оценка **предварительная**, если не у всех игроков есть данные об уроне, нормы героя или кто-то исключён из сравнения. Причина указана в подсказке и в блоке «Как посчитано».

**Хранение.** Результаты лежат в этом браузере (`dotamate.impact.v1`) по номеру матча, версии алгоритма и подписи входных данных; повторно считаются только при смене версии или входов (например, появились нормы героев). Результаты прошлых версий не смешиваются с новыми: при открытии они пересчитываются, в «Настройках» есть «Пересчитать все матчи». Это локальный расчёт, а не серверный.

**Ограничения.** Роль не определяется по имени героя; её заменяют нормы героя и бонусы поддержки. Оглушения и варды есть только у матчей, разобранных OpenDota. Отклонение от обычной игры самого игрока не используется, чтобы пересчёт был воспроизводимым. Для лучшей точности нужны разбор реплея (командные бои, предметы, объекты, Рошан) и нормы по позициям: сейчас их нет.

## Мобильная версия

Файл `css/mobile.css` (подключается последним) действует только на экранах до 759 px: поля ввода не меньше 16 px (иначе iOS приближает страницу при фокусе), зоны нажатия не меньше 44 px, читаемые мелкие подписи, фильтры матчей в две колонки, кнопки заголовка страницы в сетке, высота окон по `dvh`. `js/mobile.js` убирает кнопку помощника при прокрутке вниз и возвращает при прокрутке вверх. На сенсорных экранах подсказки показываются касанием (и пропадают через 6 с или при касании в другом месте), а фокус в текстовом поле подсказку не открывает. Проверка: `python3 tests/e2e/mobile_e2e.py`.

## Оформление и дизайн-система

Тёмная аналитическая тема без декоративных эффектов. Токены (цвета, шрифт, отступы, радиусы, тени) лежат в одном месте, `css/tokens.css`: фон `#080D12`, поверхности `#101820` и `#0C131B`, границы `#283440`, золотой акцент `#C9A66B` (только активные состояния и главное действие), красный `#F04452` (только настоящий риск и ошибки), зелёный `#48D6A0`, текст `#E8EDF3` и `#8B9AA9`. Старые имена переменных оставлены псевдонимами, поэтому прежние разделы подхватили систему без переписывания. `css/theme.css` задаёт общие кнопки, поля, вкладки и таблицы, `css/kit.css` вместе с `js/ui-kit.js` (`DMKit`) даёт переиспользуемые блоки: плашка, показатель, панель, пустое состояние, скелетон загрузки, распределение, мини-график, полоса результатов, пагинация.

Шрифт Inter лежит в `fonts/` (WOFF, подмножество кириллицы и латиницы, лицензия OFL там же), Google Fonts не используются, поэтому CSP не пускает внешние шрифты. Главная (`js/dash-ui.js`) строится только из ваших сохранённых данных: поиск игрока по нику (кандидаты OpenDota, это не доказательство личности), Steam ID или ссылке; показатели; динамика матчей и винрейт в скользящем окне; распределение игроков по сигналам репутации; таблица знакомых игроков с поиском, фильтрами, сортировкой и страницами; недавняя активность; быстрый доступ. Если данных нет, показываются пустые состояния с действием (синхронизировать, добавить матч), пока идёт загрузка видны скелетоны, а повторить синхронизацию после ошибки можно той же кнопкой «Синхронизировать». На странице профиля добавлен блок «Качество данных» (размер выборки, свежесть, достоверность, источники) и список сигналов с датами и матчами, а в карточке риска отдельно помечено, что наблюдение (факт из данных), а что вывод (расчёт Dota Mate). Анимации минимальны и отключаются системной настройкой «уменьшить движение».

## Приватность

Ваши личные оценки и заметки видны только вам. Публичны только решения модераторов о подтверждённых эпизодах и обобщённые счётчики (раздел «Репутация»), с обоснованием и возможностью оспорить. Пароли от Steam и Dotabuff не запрашиваются и не хранятся. Кнопки удаления оценок, истории и аккаунта есть в настройках.
